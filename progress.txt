## Codebase Patterns
- Project uses Next.js 16 (App Router) with TypeScript strict mode
- Prisma 7 requires driver adapters (using @prisma/adapter-pg) - no direct DB URL in PrismaClient constructor
- Prisma client is generated to `src/generated/prisma/` - import from `@/generated/prisma/client`
- Tailwind v4 with `@theme inline` for custom tokens (not tailwind.config.js)
- ESLint 9 flat config with eslint-config-next + eslint-config-prettier
- Global prisma singleton in `src/lib/prisma.ts` using adapter pattern
- Prisma 7 seed config goes in `migrations.seed` (not top-level `seed`): `migrations: { seed: "npx tsx prisma/seed.ts" }`
- Without a running DB, use `prisma migrate diff --from-empty --to-schema prisma/schema.prisma --script` to generate SQL
- Seed script must create its own PrismaClient with adapter (can't use global singleton since it runs standalone)
- Auth: NextAuth v4 config in `src/lib/auth.ts`, route handler in `src/app/api/auth/[...nextauth]/route.ts`
- Auth middleware: `extractAuth(req)` in `src/lib/auth-middleware.ts` supports JWT and X-API-Key
- Protected routes: wrap handlers with `withAuth()` from `src/lib/api-handler.ts` to inject `tenantId`
- API keys stored as SHA-256 hashes; use `hashApiKey()` from auth-middleware
- RBAC: `withTenant()` and `withRole()` wrappers in `src/lib/rbac.ts` for tenant scoping + role checks
- Tenant scoping: use `withTenantFilter(tenantId, { ...where })` to add tenantId to Prisma queries
- Role hierarchy: ADMIN > SENIOR_UNDERWRITER > UNDERWRITER (hierarchy); SIU_INVESTIGATOR, COMPLIANCE_OFFICER (independent); BROKER (restricted)
- BROKER role is auto-blocked from non-portal API paths by `withTenant` middleware
- S3 client: `src/lib/s3.ts` with `uploadToS3(tenantId, submissionId, documentId, fileName, buffer, contentType)` returning the s3Key
- S3 key path format: `{tenantId}/{submissionId}/{documentId}/{filename}`
- Multipart uploads: use `req.formData()` in App Router, iterate entries with `instanceof File` check
