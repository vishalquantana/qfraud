## Codebase Patterns
- Project uses Next.js 16 (App Router) with TypeScript strict mode
- Prisma 7 requires driver adapters (using @prisma/adapter-pg) - no direct DB URL in PrismaClient constructor
- Prisma client is generated to `src/generated/prisma/` - import from `@/generated/prisma/client`
- Tailwind v4 with `@theme inline` for custom tokens (not tailwind.config.js)
- ESLint 9 flat config with eslint-config-next + eslint-config-prettier
- Global prisma singleton in `src/lib/prisma.ts` using adapter pattern
- Prisma 7 seed config goes in `migrations.seed` (not top-level `seed`): `migrations: { seed: "npx tsx prisma/seed.ts" }`
- Without a running DB, use `prisma migrate diff --from-empty --to-schema prisma/schema.prisma --script` to generate SQL
- Seed script must create its own PrismaClient with adapter (can't use global singleton since it runs standalone)
- Auth: NextAuth v4 config in `src/lib/auth.ts`, route handler in `src/app/api/auth/[...nextauth]/route.ts`
- Auth middleware: `extractAuth(req)` in `src/lib/auth-middleware.ts` supports JWT and X-API-Key
- Protected routes: wrap handlers with `withAuth()` from `src/lib/api-handler.ts` to inject `tenantId`
- API keys stored as SHA-256 hashes; use `hashApiKey()` from auth-middleware
- RBAC: `withTenant()` and `withRole()` wrappers in `src/lib/rbac.ts` for tenant scoping + role checks
- Tenant scoping: use `withTenantFilter(tenantId, { ...where })` to add tenantId to Prisma queries
- Role hierarchy: ADMIN > SENIOR_UNDERWRITER > UNDERWRITER (hierarchy); SIU_INVESTIGATOR, COMPLIANCE_OFFICER (independent); BROKER (restricted)
- BROKER role is auto-blocked from non-portal API paths by `withTenant` middleware
- S3 client: `src/lib/s3.ts` with `uploadToS3(tenantId, submissionId, documentId, fileName, buffer, contentType)` returning the s3Key
- S3 key path format: `{tenantId}/{submissionId}/{documentId}/{filename}`
- Multipart uploads: use `req.formData()` in App Router, iterate entries with `instanceof File` check
- pdf-parse v2 uses class-based API: `new PDFParse({ data: Uint8Array })` then `.getText()` then `.destroy()`
- S3 downloads: `getFromS3(s3Key)` in `src/lib/s3.ts` returns Buffer
- Classification service: `src/services/classification.ts` with `classifyDocument(documentId)` function
- Extraction services: `src/services/extraction-acord125.ts` pattern — read doc from DB, extract PDF text via `extractPdfText(s3Key)`, regex-extract fields, store in `document.extractedData` JSON, set status to ANALYZED
- Prisma JSON fields: use `JSON.parse(JSON.stringify(data))` to satisfy `InputJsonValue` type when writing complex objects to Json columns
- Cross-doc validation pattern: `src/services/validation-cross-doc.ts` — use `findExtractedData<T>(submissionId, docType)` helper, compare values, create FraudIndicator with category CROSS_DOC
- Prisma nullable JSON where: don't use `{ not: null }` (type error), filter without it and check `!doc.extractedData` at runtime
- pdf-parse v2 metadata: use `getInfo()` → `InfoResult` with `.info`, `.total`, `.getDateNode()` for parsed dates; `getText()` → `TextResult` with `.text`
- Forensic services: fetch document with `include: { submission: true }`, create FraudIndicator with category FORENSIC per check
- Detection services pattern: `src/services/detection-statistical.ts` — main function fetches submission for tenantId, delegates to parallel check functions via Promise.all, each creates FraudIndicator with relevant category
- Industry benchmarks: `src/services/industry-benchmarks.ts` — `getBenchmark(naicsCode)` returns COGS margin range, payroll-per-head range, max revenue growth by 2-digit NAICS sector code
- Temporal detection: `src/services/detection-temporal.ts` — `detectTemporalAnomalies(submissionId)` runs coverage gap, claim timing cluster, document staleness, and impossible date checks with category TEMPORAL
- Date parsing: all extracted dates are `string | null` — use robust `parseDate()` that handles MM/DD/YYYY, YYYY-MM-DD, MM/DD/YY formats; loss run `policyPeriod` uses "date - date" format
- Financial ratio analysis: `src/services/analysis-financial-ratios.ts` — `analyzeFinancialRatios(submissionId)` runs DSO, A/R ratio, profit margin, and contents-to-building ratio checks with category RATIO
- Contents-to-building ratio ranges by occupancy: retail 20-40%, manufacturing 30-60%, office 10-30%, warehouse 15-50%, restaurant 20-45%; use `classifyOccupancy()` to map freeform occupancy strings
- Risk scoring: `src/services/scoring-engine.ts` — `calculateRiskScore(submissionId)` aggregates non-overridden FraudIndicators, returns ScoreBreakdown with totalScore, severity, and per-category points
- Routing engine: `src/services/routing-engine.ts` — `routeSubmission(submissionId)` uses ThresholdConfig (per-LOB → global → defaults) to auto-approve, escalate, refer to SIU, or assign standard review; creates AuditLog for each decision
- Dynamic API routes: use `[id]` folder naming in `src/app/api/`, params accessed via 2nd arg in withTenant/withRole handlers (e.g., `params?.id`)
- Notification service: `sendNotification(type, recipientEmail, tenantId, data)` — 4 args, tenantId is required 3rd argument
- Prisma enum in withTenantFilter: cast string literals to enum type (e.g., `"SIU_INVESTIGATOR" as Role`) when building where clauses via withTenantFilter
- Audit logging: use `logAudit()` from `src/services/audit-log.ts` for all user-initiated actions; IP address from `x-forwarded-for` or `x-real-ip` headers
- Config API routes: `src/app/api/config/thresholds/` — ADMIN-only, use `withRole(["ADMIN"])`, all mutations audit-logged with THRESHOLD_CHANGED action
- Webhooks: `dispatchWebhookEvent(tenantId, event, data)` from `src/services/webhooks.ts` to fire events to tenant subscribers; HMAC-SHA256 signature in `X-Webhook-Signature` header
- Portal layout: `src/app/portal/layout.tsx` is a server component that loads WhiteLabelConfig; wraps children in `PortalShell` (client) which provides `SessionProvider` and CSS variables for theming
- Portal white-label CSS vars: `--portal-primary`, `--portal-secondary`, `--portal-accent` set on PortalShell, consumed by child components via `var()` references and Tailwind arbitrary values like `text-[var(--portal-primary)]`
- Portal tenant resolution: uses `DEFAULT_TENANT_SLUG` env var; production should parse subdomain from host header
- Dashboard layout: `src/app/dashboard/layout.tsx` is a server component that fetches tenant name; wraps children in `DashboardShell` (client) which provides `SessionProvider` and `ThemeContext`
- Dashboard theme: use `useSyncExternalStore` for theme state (NOT `useState` + `useEffect` with `setState` — triggers `react-hooks/set-state-in-effect` lint error). Persisted in `localStorage` key `dashboard-theme`
- Dashboard dark mode: add `dark:` variant classes to all dashboard components. Toggle via `document.documentElement.classList.toggle("dark")`
- Dashboard role-based nav: `navItems` array with optional `roles` field; SIU Cases = SIU_INVESTIGATOR+ADMIN, Configuration = ADMIN, Audit Trail = ADMIN+COMPLIANCE_OFFICER
- @dnd-kit: use `useDroppable` for columns + `useDraggable` for cards; `DragOverlay` for drag preview; `PointerSensor` with distance constraint to separate clicks from drags
- Recharts: use `ResponsiveContainer` wrapping `BarChart layout="vertical"` for horizontal bar charts; Tooltip formatter type is `(value: number | undefined) => [string, string]`
- Dashboard detail pages: `mx-auto max-w-5xl space-y-6 p-4 sm:p-6` layout with rounded-xl bordered sections
- False positive API: PATCH `/api/submissions/:id/indicators/:indicatorId` with `{ justification }` body — toggles isOverridden on the FraudIndicator record
- Score override API: PATCH `/api/submissions/:id/override-score` with `{ score, justification }` body — SENIOR_UNDERWRITER/ADMIN only, directly sets riskScore and recalculates severity
- Risk report API returns ALL indicators (including overridden) with `isOverridden`, `overriddenBy`, `overrideJustification` fields; score breakdown uses only active indicators
- Action bar pattern: sticky bottom-0 with `bg-white/95 backdrop-blur-sm` for semi-transparent footer with action buttons
